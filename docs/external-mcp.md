# External MCP access policy

The official ChatGPT plugin keeps the Sites-authenticated `/mcp` connection. The Vercel deployment additionally exposes an OAuth-protected `/mcp` resource for ChatGPT custom MCP connections. Generic external bearer credentials remain disabled: `/account/mcp-token` does not issue a credential, `/api/mcp` rejects every request, and legacy token records cannot authenticate. The optional revoke path remains only so an existing account record can remove a legacy digest. Caller-supplied identity headers, client names and User-Agent values never establish identity.

The Vercel authorization server implements OAuth 2.1 Authorization Code with PKCE S256, protected-resource and authorization-server metadata, dynamic client registration, Google consent, audience-bound opaque tokens, refresh rotation and revocation. Token records are stored by digest; Google tokens are never used as MCP bearer tokens. The same standards path is intended for Claude, but Claude host compatibility remains unverified until a real connector sign-in and tool call succeed. No fixed Authorization header or access key is advertised. Official references checked 2026-11-02: https://developers.openai.com/plugins/build/auth, https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp and https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization

The `kongboda_live_briefing` tool exposes a standards-first MCP Apps resource (`text/html;profile=mcp-app`, `_meta.ui.resourceUri`) and the ChatGPT compatibility output template. Its interactive panel has Summary, Timing, and Strategy/Environment tabs. Structured output includes a verified leaderboard, current tyre stints, weather, track status and the latest race-control message; hosts without MCP Apps UI receive the same point-in-time result as text. LIVE is displayed only when the session, collector and current `TimingData` freshness checks all pass. Strategy signals additionally require current `TimingAppData`; otherwise the panel explicitly withholds the inference.

This is an on-demand snapshot surface, not a continuously updating broadcast. A new tool call refreshes it. The Vercel OAuth routes and MCP challenge are covered by automated end-to-end tests, but real host rendering and sign-in must still be smoke-tested in ChatGPT and Claude after deployment; no background or unsolicited chat message is promised. The existing Sites-authenticated ChatGPT connector remains available independently.

Shared F1/WEC collector tools require a current crew grant or owner identity when the access-key gate is configured. Nonmembers cannot borrow the shared account. Personal F1/FIAWEC+ credential connections remain unavailable: there is no verified public account-integration contract for this service, and F1 subscription credentials or timing data must not be collected or republished through an unofficial login flow.

The MCP server advertises `tools.listChanged=true`. Authenticated GET streams last up to 60 seconds and check the shared catalog version every 15 seconds. Each current `tools/list` publishes a fingerprint excluding the owner roster. After a deployment, the release smoke test must call authenticated `tools/list` to publish the new fingerprint. Existing streams emit `notifications/tools/list_changed` and close when this fingerprint changes. Clients must reconnect the stream and handle the notification; phone push, background delivery and automatic refresh in a particular AI are not guaranteed. Clients without streaming support must refresh their connection manually.
